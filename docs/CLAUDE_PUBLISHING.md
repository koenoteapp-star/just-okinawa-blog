# Claude Code向け：JUST OKINAWA 自動投稿運用

この説明書は、新デザインの導入後に既存の自動投稿処理へ組み込むためのものです。新しいスケジュールやアカウントは作りません。既存の投稿時刻・GitHub/Vercel連携・承認条件を引き継いでください。

## 1. 日々の投稿で変更するもの

- 新しい英語記事：`src/content/blog/<english-kebab-slug>.md`
- 記事写真：`src/assets/blog/<descriptive-name>.webp`
- 必要な出典記録：記事frontmatterと本文。

**通常の投稿では `src/pages/`、`src/components/`、`src/styles/`、`src/data/`、schema、既存の記事URLを変更しないでください。** 記事を追加してAstroを再ビルドするだけで、次の場所へ自動で反映されます。

| 表示先 | 反映条件 |
| --- | --- |
| トップページ最新6件 | 公開済み記事をpubDateの新しい順に表示 |
| `/blog/` | 全公開記事、12件ずつ。月は日本時間基準。検索・島・体験・月の複合絞り込み |
| `/islands/<destination>/` | destinationが一致する最新6件 |
| `/experiences/<experience>/` | experiencesに含まれる最新9件 |
| 記事下の関連記事 | 同じ島を優先し、その中で新しい順に3件 |
| sitemap.xml | 公開済み記事だけ掲載 |

トップのメイン写真とブランドコピーは記事と独立しています。毎日の投稿で第一印象が変わることはありません。`featured`は将来の編集用に予約されていますが、現時点の並び順には影響しません。

## 2. 投稿に必要なfrontmatter

`docs/POST_TEMPLATE.md`を参照してください。テンプレートは`src/content/blog/`に置かないでください。実際の記事を作るときにコピーして全項目を埋めます。

| 項目 | ルール |
| --- | --- |
| title | 英語。内容と一致する具体的なタイトル |
| description | 英語の簡潔な要約。本文を読む理由を書く |
| pubDate | `"2026-09-26T09:00:00+09:00"` のような引用符付きISO日時。日本時間+09:00を明示 |
| updatedDate | 既存記事を更新した場合のみ。pubDateは変更しない |
| heroImage | 記事ファイルから画像への相対パス。通常 `../../assets/blog/name.webp` |
| heroAlt | 実写真の内容と確認済みの場所を英語で説明 |
| destination | 下表から1つ |
| experiences | 下表から1つ以上を配列で指定 |
| draft | 作成中はtrue。公開準備完了後にfalse |
| imageCredit | 撮影者／提供元 |
| imageSource | 権利と撮影地を確認できる実在のHTTPSページ。本人所有の写真は所有者提供の参照先を使う。参照先が未用意なら公開を止めて所有者へ報告 |
| affiliateLinks | 任意。既存の承認済みURLのみ使う。booking / viator / amazon / youtubeVideo |

| destination | 対象 |
| --- | --- |
| main | 沖縄本島 |
| kerama | 慶良間諸島 |
| miyako | 宮古諸島 |
| yaeyama | 石垣・竹富・西表など八重山諸島 |
| kume | 久米島 |

| experiences | 分類 |
| --- | --- |
| ocean | 海・ビーチ・海の体験 |
| culture | 文化・歴史・集落・工芸 |
| food | 食・市場・飲食店 |
| nature | 自然・景観・アウトドア |

サイト全体に関する記事や複数地域にまたがる記事は、主題の島を1つ選ぶか、適切な分類設計が必要な旨を報告してください。分類IDを勝手に追加しないでください。旧記事は分類なしでも表示されますが、島別・体験別一覧には入りません。既存記事への分類追加は、内容を読んだうえで行います。

## 3. 1記事を公開する手順

1. リポジトリのCLAUDE.md / AGENTS.mdとこの説明書を読む。現在のブランチ、変更状況、既存の投稿処理を確認する。
2. 類似タイトル・スラッグ・既存記事を検索し、重複投稿を防ぐ。同じ日の実行が再試行された場合は新規記事を増やさず、対象の記事が既に存在するかを確認する。
3. 公式観光情報、交通機関、店舗の公式ページなどで変動する情報を確認する。料金・運航・営業時間・所要時間を推測しない。
4. 利用権限と撮影場所が確認できる画像を用意する。別の島の写真を流用してその島と表示しない。画像はローカルに保存し、2MiB未満、目安1600px程度に圧縮する。実景紹介の代わりにAI生成風景を使わない。
5. まずdraft:trueで記事を書く。見出しは##から始める。実体験を捏造しない。既存の島ページ・関連記事へ正しい内部リンクを追加する。
6. 下の検証を実行し、記事・画像・内部リンクを確認する。
7. 公開可能な時刻になり、内容の確認が済んだらdraft:falseにする。`--publish`付きで再検証する。
8. 既存の承認済み公開手順に従って必要なファイルだけをコミット・pushする。未知のリモート、ブランチ、Vercelプロジェクトを推測しない。既存の自動公開許可がなければ、ビルド済みの差分と確認結果を報告する。
9. デプロイの成功を確認する。実URLで新記事、トップ最新欄、島別、体験別、画像、リンクを確認してから「公開完了」と報告する。

```bash
# 初回のみ。既存プロジェクトに未導入なら追加する
npm install -D gray-matter

# 下書き検証（実在する新記事のパスに置き換える）
node scripts/validate-post.mjs src/content/blog/your-real-slug.md

# 公開前検証
node scripts/validate-post.mjs src/content/blog/your-real-slug.md --publish
npm run check
npm run build
```

既存プロジェクトにcheckコマンドがない場合は、初回導入時に`@astrojs/check`と`typescript`を追加し、`"check": "astro check"`をpackage.jsonのscriptsへ追記します。既存のscriptsは消さないでください。

検証スクリプトは形式・画像の存在・公開日時を確認します。本文の事実性、画像の権利、リンク先の営業状況まで保証するものではありません。失敗を無視して公開しないでください。

## 4. 日時・未来記事・下書き

- 全一覧・記事ルート・sitemapで`draft !== true && pubDate <= ビルド時刻`を共通条件にします。
- 未来日時のファイルはビルド時に除外されます。時刻を過ぎても公開済みの静的ファイルは自動更新されません。
- 予約公開をする場合は、既存の自動投稿ジョブが該当時刻以降に再ビルド・デプロイする必要があります。ファイルを先にpushしただけでは予約公開完了ではありません。
- 投稿日時を現在時刻にして即時ビルドする通常の運用が最も単純です。
- 既存RSSがある場合も同じ公開条件を適用してください。導入手順書を参照。

## 5. Claude Codeへ渡す日次指示文

以下を既存の自動投稿ジョブの指示に組み込めます。

> このリポジトリの既存ルールとdocs/CLAUDE_PUBLISHING.mdを読み、JUST OKINAWAの新しい英語記事を1本作成してください。既存記事との重複を確認し、実在する公式情報と利用可能な実写真を使ってください。通常の変更範囲は記事・記事画像に限定し、destination、experiences、heroAlt、画像出典、タイムゾーン付きpubDateを必ず設定してください。下書き検証、公開前検証、型チェック、Astroビルドをすべて通し、既存の承認済み公開フローに従ってください。公開前の確認不足やコマンド失敗があれば停止し、原因を報告してください。公開後は実URL、記事スラッグ、分類、使用画像、検証結果、デプロイ結果を報告してください。新しいSNS投稿や第三者への送信は行わないでください。

## 6. 更新・取り消し

既存記事を修正するときはファイル名とpubDateを保持し、updatedDateを更新します。取り下げるときはdraft:trueにして再ビルド・デプロイします。URLを変える場合はリダイレクトを別途計画します。ファイルの削除やリポジトリ全体の上書きで対応しないでください。
